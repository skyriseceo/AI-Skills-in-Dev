# Skill Assessment

**Task:** Redesign an existing SaaS analytics dashboard (working product UI) so it stops looking AI-generated/templated and feels premium — routing assessment only, no execution yet.

**Plan:**
1. `taste-skill:redesign-skill` — primary: audits the current dashboard, identifies the generic-AI patterns (stock gradients, interchangeable cards), and applies high-end standards to the existing code — why it wins: its contract is *exactly* this artifact and mode. It is scoped to "upgrades existing websites and apps to premium quality," explicitly claims "identifies generic AI patterns," works with any CSS framework, and promises not to break functionality — critical for a live work dashboard. Under the specificity rule, a skill scoped precisely to redesign-of-existing beats general design skills that span the whole family.
2. `dataviz` — supporting: governs the chart/graph/KPI-tile layer during the restyle — why: an analytics dashboard's core content is data visualization, and this skill's contract demands it be read before touching any chart, stat tile, palette, or dashboard layout. The redesign skill sets the overall design language; dataviz keeps the charts reading as one coherent, accessible system inside it. Genuinely distinct layer, so the mix is justified.

**Considered and rejected:**
- `design-master` — the closest runner-up; it explicitly claims "UI feels... 'AI-generated' and needs to feel premium" and covers dashboards. It loses on specificity: it is the general-purpose skill spanning the whole design family (builds, motion, reviews, greenfield), while redesign-skill is purpose-built for exactly this job — upgrading an existing app without breaking it. What would flip the call: a greenfield build, a motion-heavy brief, or wanting its critique/loop/variants modes rather than a straight redesign.
- `impeccable:impeccable` — broad UX/audit coverage including dashboards, but it's a generalist critique-and-improve skill; it would spend effort on UX/IA/accessibility breadth when the stated problem is aesthetic genericness. Loses the specificity tiebreak the same way design-master does.
- `taste-skill:taste-skill` — anti-slop and audit-first on redesigns, but it's the family's general landing-page/portfolio skill; redesign-skill is the same family's dedicated redesign tool, so the family's own specialization wins.
- `taste-skill:soft-skill` — defines premium fonts/spacing/shadows and blocks cheap defaults, but it's a style rulebook, not a redesign process; redesign-skill subsumes that role for this task.
- `frontend-design:frontend-design` — aesthetic-direction guidance for new or reshaped UI, but thinner coverage: direction advice without the audit-and-upgrade process an existing app needs.
- `emil-design-eng` — polish-and-details philosophy; valuable sensibility but covers the last 10% (micro-polish), not the structural de-genericizing this dashboard needs first.
- `taste-skill:minimalist-skill` / `taste-skill:brutalist-skill` — each imposes one specific aesthetic; the user asked for "premium," not a predetermined style. Picking a lane belongs inside the redesign, not at routing time.
- `taste-skill:imagegen-frontend-web` / `taste-skill:image-to-code-skill` / `taste-skill:stitch-skill` / `taste-skill:brandkit` — wrong output mode: they produce design images/reference comps/design-system docs, whereas this task ends in restyled working code for an existing app.
- `superpowers:brainstorming` — a process skill that would normally front-run creative work, but the intent is already settled (de-genericize, feel premium, same dashboard); re-running discovery on a settled decision is friction, not rigor.
- `taste-skill:gpt-tasteskill` — landing-page structure (AIDA, hero rules) and GSAP scroll theatrics; wrong genre for a product dashboard.

**Blockers:** No dashboard code or URL was provided. Before execution, the actual codebase (framework, CSS approach) or at least a live URL/screenshots is needed for the audit step.

**Verdict:** Run `taste-skill:redesign-skill` as the primary to audit and upgrade the existing dashboard, with `dataviz` applied to the chart/KPI layer during the restyle — not executed yet per the user's request, and blocked until the dashboard code or URL is supplied.
